## 记忆系统优化方案

深入分析了 `lib/memory/` 全部 23 个文件 (~253KB) 后，生成了详细优化方案（`.workbuddy/analysis/memory-optimization-plan.md`）：

**P0 紧急优化（3项）**:
- 向量搜索加 ANN 分桶索引（O(n) → O(n/256)）
- 编译流水线并行化（today+week 并行，省 ~30% 时间）
- 嵌入批量化（减少 API 调用和 DB 写入开销）

**P1 核心优化（4项）**:
- 质量评估异步化+采样（解决 O(n²) 阻塞）
- FTS5 优化器与主库合并（消除独立数据库）
- 编译指纹分级（减少无效重编译）
- JS 端余弦计算替代 C 扩展

**P2 架构优化（5项）**: FactStore 拆分、编译缓存落地、摘要增量、目录重组、连接复用

## Phase 2 实施完成

实施了 4 项优化，修改 5 个文件 + 新增 1 个文件，基线对比零新增失败：

**P1-3 编译指纹分级** (`compile.js`):
- compileToday + compileWeek 指纹从整体 MD5 改为 session_id 分组 JSON
- 仅新增/变更的 session 触发重编译，6/7 session 不变时跳过 LLM 调用

**P1-1 质量评估异步+采样** (`quality-scorer.js`):
- `scoreConsistency()` 从全量 O(n²) 改为同标签过滤 + 蓄水池采样（maxRelated=100）
- 500 条事实一致性检查从 ~12.5万次比较降到 ~最多100次

**P1-2 FTS5 单库化** (新增 `fts5-query-builder.js`, 修改 `fact-store.js`):
- CJK ngram 分词 + 同义词扩展从独立 DB 移到查询时动态构建
- `enhancedSearchFullText` 直接对 facts_fts 执行增强查询，删掉 optimized_facts.db 依赖

**P0-1 向量分桶索引** (`vector-search.js`):
- 8 维分桶 + SQLite indexed_bucket 索引，三阶段渐进搜索
- Phase 1: 同桶+1-bit翻转（~11%数据）→ Phase 2: 2-bit → Phase 3: 全表兜底
- searchByVector 从 O(n) 降到 O(n/256) 典型场景
